# 技能更新与移动

## 用户入口

「我的技能」和技能详情提供两个独立按钮：

- **更新**：上传新包，绑定原 Skill ID，沿用当前空间和可见范围。
- **移动**：将整个技能迁入有发布权限的目标空间，自动使用最新可用版本。

删除「保存私有版本 → 选择版本 → 分享」的中间流程。首次发布仍可选择「仅自己可见」，私有技能可继续通过更新上传新版本；已有私有历史保留。

版本行不再提供分享入口。移动对话框只显示最新可用版本和目标空间，不提供版本选择或「谁可以访问」选项。

## 更新规则

更新走现有包校验、安全扫描和审核流程，通过后才切换当前版本。团队管理者沿用现有扫描后免人工审核规则，超级管理员的定向更新也必须先通过扫描。私有技能沿用私有上传和个人使用规则。

服务端以 Skill ID 定位技能，验证作者、空间发布权限及包内名称。客户端不能通过更新参数改变空间或可见范围；已移入共享空间的技能不能再通过旧私有上传地址创建私有中间版本。更换空间必须使用移动。

扫描、审核中或失败时，当前已发布版本保持可用。

## 最新可用版本

- 已共享技能：使用 `latestVersionId` 指向的已发布、已共享且文件就绪的版本。
- 私有技能：从文件就绪的 `UPLOADED`、`PUBLISHED` 版本中，按创建时间、ID 选最新版本。
- 不选择 `DRAFT`、`SCANNING`、`SCAN_FAILED`、`PENDING_REVIEW`、`REJECTED`、`YANKED` 版本。
- 没有可用版本时提示先更新；后端在预检查和提交时解析版本，客户端不能指定旧版本。
- 提交后绑定版本和独立扫描记录；若审核前最新可用版本发生变化，原移动不生效，需刷新后重新申请，避免将当前版本回退。

例如 v2 正在审核、v1 已发布时，移动使用 v1。

## 移动流程

1. 作者选择目标空间：仅包含自己有发布权限的有效空间，排除当前空间和系统私有空间。
2. 预检查目标权限、空间状态、名称冲突、版本资格和实际包内容；沿用现有告警确认。
3. 提交独立移动申请并安全扫描；普通作者进入目标空间审核，超级管理员扫描通过后生效。
4. 扫描和审核期间，原空间、可见范围及已发布版本不变，原技能正常使用。
5. 审核通过，在同一事务内迁移整个技能，将可见范围固定为 `NAMESPACE_ONLY`，更新申请状态。

移动成功后：

- Skill ID、作者、slug、版本及文件关联、收藏、订阅和历史记录保留。
- 原空间不留副本，已共享技能可再次移动。
- 仅目标空间成员可见，不提供公开选项，不支持移回个人私有空间。
- 已共享历史版本的可见范围随目标空间调整，私有历史继续保持私有。
- 原空间未完成的更新审核自动撤回，版本变为 `UPLOADED`，保留文件；扫描自动发布标志清除，迟到结果不能使这些旧更新发布。作者可通过更新按新空间规则重新提交。
- 稳定链接 `/skills/by-id/{skillId}` 解析新坐标；详情页在移动完成后跳转该入口，避免继续读取失效的旧空间地址。

## 失败与权限边界

目标空间任何同名技能均阻止移动，不覆盖、不合并。归档、隐藏、空间冻结、权限丢失、文件不完整、扫描不通过均阻止生效。

撤回、拒绝或失败保留原技能和文件。审核阶段再次验证目标权限、名称和版本；新发现的冲突不会造成半迁移。移动申请独立于版本生命周期，使用现有 `SCANNING`、`PENDING_REVIEW`、`COMPLETED`、`REJECTED`、`WITHDRAWN`、`FAILED` 状态。

同一 Skill 只允许一个活动移动申请，幂等键重复提交返回原结果。按 ID 顺序锁定源和目标空间，并沿用技能操作锁、版本乐观锁。提交、生效、拒绝和结束仍记录审计。

原私有地址仅按作者身份解析原技能，不为其他用户提供跨空间权限。移动后按当前容器和版本权限重新校验详情、下载、文件、历史和 diff。

## 接口

路径同时支持 `/api/web` 和 `/api/v1`；为复用已有申请记录，移动接口保留内部 `sharing` 命名。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/skills/by-id/{skillId}/sharing` | 查询当前坐标、最新可用版本（零或一个）、目标空间、最近申请 |
| POST | `/skills/by-id/{skillId}/sharing/precheck` | 检查目标及最新可用版本 |
| POST | `/skills/by-id/{skillId}/sharing` | 提交移动申请，服务端选择版本并固定目标成员可见 |
| POST | `/skills/by-id/{skillId}/sharing/{requestId}/withdraw` | 撤回活动申请 |
| POST | `/skills/by-id/{skillId}/versions` | 上传更新，服务端继承空间及可见范围 |
| GET | `/skills/by-id/{skillId}/location` | 授权后解析当前坐标 |

移动请求仅包含 `targetNamespaceId`、`idempotencyKey`、`confirmWarnings`。更新上传包含 `file` 和 `confirmWarnings`。原 `/private-versions` 接口删除。前端契约由 `make generate-api` 自动生成。

## 验证

- `SkillSharingServiceTest`：最新版本选择、固定范围、权限、冲突、撤回、扫描失败、原审核撤回和历史保留。
- `SkillSharingFlowIntegrationTest`：真实 HTTP 授权与事务、已发布技能跨空间迁移、源审核失效、私有历史隔离和文件保留。
- `SkillPublishServiceTest`、`SkillPublishControllerTest`：定向更新、继承范围、包校验和告警确认。
- `web/e2e/skill-sharing.spec.ts`：独立更新、无版本/受众选择、再次移动、名称冲突、键盘、撤回和窄屏。
- `scripts/sharing-smoke-test.py`：真实扫描、目标审核、直接更新、再次跨空间移动及旧审核撤回；使用临时作者和技能，结束后清理技能与目标空间。
